# TV Shows Explorer

Поиск сериалов через [TVmaze API](https://www.tvmaze.com/api): выдача по 3 на страницу, фильтр по жанрам, вход по email, личное избранное, загрузка и ошибки.
Учебный проект на буткемпе Simple Architecture — каждую неделю развивается под тему новой лекции.

Открыть: https://tv-shows-explorer-nine.vercel.app

Сайт: React 19 · TypeScript · Vite · MobX · React Router · CSS Modules. Сервер: Express на Node 24. Хостинг обоих: Vercel. Проверки: oxlint.

```sh
npm install
npm run dev     # сайт (Vite) и сервер (Express, порт 3001) вместе
npm run build   # сборка и проверка типов сайта и сервера
npm run lint    # oxlint + проверки размера файлов и тегов вне ui-kit
```

## Кто что делает

Сайт показывает и спрашивает, сервер решает. В TVmaze ходит только сервер.

- **Сервер**: разговор с TVmaze и кеш его ответов на 5 минут, фильтр по жанру, нарезка страниц по три, счётчики жанров, вход по email и сессии, избранное у каждого пользователя своё.
- **Сайт**: ввод запроса с паузой, обрыв устаревшего запроса, загрузка и ошибки, показ пришедшей страницы, страница входа, звёздочки, панель избранного и toast.

Гость ищет и смотрит шоу; звёздочка у него показывает сообщение с кнопкой «Войти». Вышел и вошёл под тем же email — прежний список на месте.

Кеш, сессии и пользователи с избранным лежат в памяти сервера, в обычных объектах, без базы. Локально они живут, пока работает сервер. На Vercel память обнуляется примерно через 5 минут без запросов и при каждом деплое: сайт скажет «Вход истёк», войти можно снова, но список будет пустой.

## Структура

```
api/index.ts                 вход сервера для Vercel: одна строка
contract/                    типы данных, которыми обмениваются сайт и сервер: Show, ShowsPage, Session, ApiErrorKind
server/
  app.ts                     приложение Express, одно на все маршруты
  listen.ts                  локальный запуск
  routes/                    маршруты: разбирают запрос и достают ключ сессии, вызывают таску, выбирают код ответа
  tasks/                     таски: searchShows, logIn, logOut, addFavorite, removeFavorite, getFavorites
  api/tvmaze/                транспорт и методы API TVmaze, перевод ответа в Show
  stores/                    данные в памяти: cache.ts, sessions.ts (ключ → email), users.ts (email → избранное)
src/
  ui-kit/                    атомы без логики и предметной области: Text, Button, Input, Link,
                             Image, Icon, Chip, Dialog, LiveStatus
  app/                       корень: адреса → экраны, презентер корня восстанавливает сессию до первого кадра
  components/Brand/          логотип, нужный обоим экранам
  screens/
    login/                   страница входа: поле email, таска logIn
    explore/                 поиск
      Explore.tsx            разметка экрана
      logic/                 логика экрана: usePresenter.ts, useShowSearch.ts (все запросы поиска),
                             useFavoriteToggle.ts (звёздочка), tasks/ (таски экрана)
      Account/ SearchInput/  блоки, нужные только этому экрану: вход и выход в шапке, поле поиска
      SearchState/           заглушки: пусто, загрузка, ошибка, ничего не найдено
      SearchResults/         жанры, карточки, пагинация
      Favorites/             кнопка со счётчиком и боковая панель со списком
      components/Toast/      сообщение, нужное и экрану, и панели избранного
  tasks/session/             таски сессии, нужные двум экранам: rememberSession, forgetSession
  stores/                    сторы MobX: searchStore, favoritesStore, toastStore, userStore (email и ключ)
  api/                       транспорт (client.ts, сам ставит заголовок Authorization) и методы API нашего сервера
  types/                     свои типы сайта: исходы тасок
  locales/                   все тексты интерфейса: ru.ts, а index.ts отдаёт выбранный язык
  styles/                    tokens.css (цвета, шрифты, отступы) и global.css
scripts/                     проверки для npm run lint и ux-shots.mjs — снимки экрана для ревью удобства
```

Компонент — папка `<Name>/` с `<Name>.tsx`, рядом `<Name>.module.css`, при логике `logic/usePresenter.ts`, дочерние компоненты — папками тут же.
Компонент лежит рядом с тем, кто его использует; нужный двум местам переезжает в `components/` их общей папки, двум экранам — в `src/components/`.

## Как идёт поиск

```
сайт:    view → usePresenter → таска → src/api ──────┐
              ↑ исход          ↓ страница выдачи     │  GET /api/shows?q=…&genre=…&page=…
              └────────── searchStore → view         │
                                                     ▼
сервер:  маршрут → таска → server/api/tvmaze → TVmaze
                     ↓↑
              stores/cache (5 минут)
```

View — только разметка. Презентер вызывает таску и ждёт её исход: загрузку и ошибку он держит у себя. Таска кладёт пришедшую страницу в стор; стор только хранит, в сеть не ходит. На сервере цепочка та же: маршрут вызывает таску, таска берёт выдачу из кеша или из TVmaze, фильтрует и режет на страницы. Формат TVmaze виден только в `server/api/tvmaze/`.

Избранное идёт тем же путём: звёздочка → презентер блока → таска → `PUT` или `DELETE /api/favorites/<id>` → сервер находит пользователя по ключу сессии, сохраняет шоу и отдаёт обновлённый список → `favoritesStore`.

## Как идёт вход

```
вход:     форма → usePresenter → таска logIn → POST /api/session { email }
          сервер: маршрут → таска logIn → users[email] (создаёт при первом входе), sessions[token] = email
          ответ { email, token } → userStore + localStorage

дальше:   каждый запрос сайта несёт Authorization: Bearer <token>
          сервер: маршрут достаёт ключ → таска ищет сессию → нет сессии — 401
```

Ключ сессии — случайная строка, выход стирает её на сервере. Транспорт берёт ключ через функцию, которую `main.tsx` передаёт ему при старте: о сторах он не знает. Получила таска 401 — она сама забывает сессию, а презентер показывает «Вход истёк».

Слои сайта импортируются через алиасы: `@ui-kit/`, `@components/`, `@tasks/`, `@stores/`, `@api/`, `@app-types/`, `@locales/`, `@contract/`. В коде сервера импорты только относительные.
